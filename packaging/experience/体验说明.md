# Jev 0.1.6 本地体验

发布负责人完成新目录的清单核对、启动检查和 Defender 扫描后，打开交付的 0.1.6 入口，或直接双击完整目录里的 `jev-chat-windows.exe`。启动不要求终端确认；请勿移动单独一个 exe。本轮保留 0.1.5 包、旧启动器和原快捷方式目标供回退；实际发布结果以交付记录为准。

1. 左侧有“工作区”“示例体验”“设置”。先进入“示例体验”：虚构聊天、离线预置结果，无需 Key，不联网也不能填入微信。左侧 Key 状态可能显示“状态待确认”；它不表示已经连接或验证服务。
2. 用自己的对话时，打开“设置”填写一个 OpenRouter Key。保存是可选的；选保存时由 Windows 凭据管理器保管，不写入明文配置。
3. 打开目标微信聊天，点击“读取当前聊天”。在“对话与分析”区核对说话人和内容，可编辑、删除或脱敏，关系、口吻与群聊选项按需展开；然后点击底部“生成回复”。只有主动分析才将确认文字交给 OpenRouter 起草与 Jev 判断。
4. 宽窗口同时显示对话与回复；窄窗口用“对话分析 / 回复建议”切换，不会重新分析或清空草稿。“回复草稿”区显示一个可编辑草稿，其余备选默认可见并可滚动；换选后保留每条已编辑内容，只有一条候选时不显示空列表。文字统一使用黑体，系统缺少时回退微软雅黑或系统字体。Jev 逐条分析在对话区查看。想让模型重写时，展开改写要求并明确点击“按要求改写”。概率、“真实意图”和安全判断都不是事实保证，尤其核对时间、承诺和过往经历。
5. 只有当前编辑框在条件满足时提供填入；追加到微信输入框后，由你检查并手动发送。一份结果成功填入一次后，编辑、换选都不能再次填入。手工内容和示例只能复制。
6. 分析、改写只使用已经确认的消息，不会在生成时重新读取微信。填入前严格复核：漏读、截断等造成“暂时无法确认”时保留选中和编辑，取消遮挡后手动重试；明确有新消息或目标变化时，草稿仅复制，请重新读取、确认、分析。标题只接受规范化后相等，相似联系人不会放行。结束时清除本次内容或退出；清除不会删除主动保存的 Key，“忘记已保存 Key”才会删除它。

首次读取的 OCR 仍需你核对；完整标题识别错误也可能要求重新读取。原生 Qt 合成流程测试使用外部替身，不代表真实遮挡 OCR、回复质量或用户验收通过。

如启动失败，保留整个新目录和错误文字，不要覆盖旧版或运行安装脚本。正常启动后按上面步骤直接使用即可。
